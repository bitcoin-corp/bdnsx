# bDNSX record formats, v1

Every bDNSX record is one `OP_FALSE OP_RETURN` output, signed by the vault key with AIP.

```
OP_FALSE OP_RETURN
  19HxigV4QyBv3tHpQVcUEQyq1pzZVdoAut "" text/plain utf-8        # B (empty body)
  |
  1PuQa7K62MiKCtssSLKy1kh56WWU7MtUR5 SET app bdnsx type <type>   # MAP
    <key> <value> ...                                            # fields, fixed order, see below
    v 1
  |
  15PciHG22SNLQJXMoSUaWVi7WSqc7hCfva BITCOIN_ECDSA <address> <signature>   # AIP
```

- **Signed bytes (AIP):** `0x6a` followed by the UTF-8 bytes of every push before the AIP pipe, concatenated
  (B prefix through `v 1`). Signature is a Bitcoin Signed Message (BSM) compact signature, base64.
  `<address>` is the vault P2PKH address; verifiers recover the key from the signature and compare.
- **Field order is fixed** per type (below). Optional empty fields are omitted. Unknown keys make a record invalid.
  A decoder must re-encode and get the same pushes, otherwise the record is rejected (non-canonical).
- **Keys** (`renter`, `to`, `key`) are compressed secp256k1 identity public keys, hex.
- **Dates** are ISO 8601 UTC, second precision (`2027-11-01T00:00:00Z`). `usd` is a decimal string, 2 places.
- `paid` / `prev` are txids (hex, 64 chars). `prev` points at the record tx this one supersedes.

| type | fields (in order) | meaning |
|---|---|---|
| `lease` | name, renter, from, until, paid, usd | New lease of a vault-held name |
| `renew` | name, renter, until, paid, usd, prev | Extends `until` (from the old expiry, not from today) |
| `transfer` | name, renter, to, until, prev, fromsig, tosig | Lease moves from `renter` to `to`; same `until` |
| `link` | domain, key, name? | `domain` proven (DNS TXT) to belong to `key` |
| `revoke` | name, renter, prev, reason | Owner ends a lease early. Always public |

## Party signatures

Renters prove control of their key with a BSM signature (base64 compact) over a plain UTF-8 message:

| Action | Message | Signed by |
|---|---|---|
| lease | `bdnsx:lease:<name>:<years>:<paymentTxid>` | renter |
| renew | `bdnsx:renew:<name>:<years>:<paymentTxid>` | current renter |
| transfer (out) | `bdnsx:transfer:<name>:<fromKey>:<toKey>:<until>` | current renter → `fromsig` |
| transfer (accept) | `bdnsx:accept:<name>:<fromKey>:<toKey>:<until>` | new renter → `tosig` |
| link | `bdnsx:link:<domain>:<key>` | key holder, published at TXT `_bdnsx.<domain>` |

The payment txid is the nonce: each payment can be used once, so a captured signature cannot be replayed.

## Test vectors

`vectors.json` is generated by `pnpm vectors` from a TEST-ONLY key (`sha256("bdnsx-test-only:vault")`).
`src/record.test.ts` checks that the committed file matches the generator and that every vector decodes and verifies.
